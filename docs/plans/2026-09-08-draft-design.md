# 剪易草稿功能设计

## 目标

为浏览器版剪易增加本地草稿能力。用户可以保存多个作品，退出页面后从草稿列表选择并恢复指定作品。草稿包含时间线配置和素材副本，不依赖原始文件路径。

## 已确认的交互

- 启动网页时先显示草稿列表，由用户选择“新建草稿”或打开已有草稿。
- 顶部显示当前草稿名称和保存状态。
- 支持新建、打开、重命名、复制和删除草稿。
- 导入的视频、音频、图片和 GIF 复制到浏览器本地，作为当前草稿的素材副本。
- 用户完成导入、拖动、编辑、分割等操作后延迟自动保存，建议延迟约 800 毫秒。
- 播放和导出期间暂停自动保存；页面隐藏时尽力保存，关闭前有未保存修改时提示。关闭时不承诺异步事务完成。
- 草稿封面使用当前预览画面的缩略图。

## 数据结构

使用 IndexedDB，至少包含 `drafts` 和 `assets` 两个 object store。

`drafts` 保存：

```text
id, name, createdAt, updatedAt, schemaVersion
cover, duration, selectedClip, playhead, project
```

`project` 保存视频片段、文字、画中画、音频、画布比例、音量、特效和转场等 JSON 配置。片段中的素材只保存 `assetId`，不保存 Blob。

`assets` 保存：

```text
id, name, type, size, lastModified, blob
```

草稿通过 assetIds 引用素材。复制草稿时仅复制配置并共享素材记录；不重新读取原始路径。删除或保存草稿时，在同一事务中清理不再被任何草稿引用的素材。

## 模块边界

新增 `draft-store.js`，负责 IndexedDB 初始化、版本检查、草稿 CRUD 和素材 Blob CRUD。新增 `draft-manager.js`，负责草稿列表、恢复流程、自动保存队列、保存状态和错误提示。新增 `draft-editor.js` 负责工程快照与恢复；`app.js` 继续维护剪辑状态，并保留原素材文件与字体供适配层使用。

## 恢复流程

用户在列表选择草稿后，先读取 JSON，再读取关联 Blob 并创建对象 URL；随后恢复素材源、视频片段、覆盖轨道、画布设置、选择状态和播放头，最后重新加载媒体并刷新预览。素材缺失时标记草稿并允许重新选择对应文件。

实现时先完成新素材解码与校验，再替换当前作品。版本 1 以外的快照明确拒绝，尚无历史版本需迁移。重新关联时按文件名和大小匹配，恢复成功后另存副本。转场末帧缓存和 GIF 帧均重新解码生成，不放入 JSON。

## 异常和边界

- IndexedDB 写入空间不足时显示明确错误，保留内存中的编辑状态。
- 保存失败不得显示“已保存”。
- `schemaVersion` 用于未来数据迁移。
- 浏览器清理站点数据会删除本地草稿，需要在帮助文案中说明。
- 导出或播放中关闭页面不保证任务恢复，只保证最近一次成功保存的编辑状态。

## 第一版验证

验证新建、保存、刷新后草稿列表、打开恢复、重命名、复制、删除及素材 Blob 清理；覆盖多段视频、文字、贴纸、画中画、音频、特效和转场。额外验证空草稿、损坏素材、存储失败提示和 schema 版本迁移入口。

## 本地文件夹扩展

`draft-folder.js` 提供与浏览器后端一致的 list/get/save/change 接口，复用快照和恢复模块。用户选择目录后，在专用 `jianyi-drafts/` 下保存 `project-index.json` 和 `assets/<assetId>`；浏览器只持久化目录句柄，刷新后由用户点击重新授权。

首次切换位置先保存原草稿，再把当前作品另存到目标目录；全部成功后才切换当前后端。素材使用稳定标识复用，自动保存不重复复制。先写素材再提交清单，清单写入失败时 abort 保留旧版本；目录里的孤立素材允许稍后手动清理。删除草稿只修改清单，清理操作在同一个写入锁内核对所有草稿引用，不触碰专用目录外的文件。

同源页面使用 Web Locks 串行修改清单，文件流采用 exclusive 写入，并校验草稿 revision。不同浏览器不承诺并发协作。备份时需要复制整个专用目录；文件夹模式减少浏览器存储配额占用，不替代解码与预览的内存优化。
